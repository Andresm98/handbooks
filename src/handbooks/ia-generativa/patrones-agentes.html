Conviene distinguir dos familias. En los workflows, el código define el camino y el LLM resuelve pasos dentro de él: son predecibles, baratos de probar y suficientes para la mayoría de casos. En los agentes, el LLM decide el camino. Los patrones de abajo van de más determinista a más autónomo; empieza siempre por el más simple que resuelva el problema.

Patrones de agente

ReAct (Reason + Act)

El agente alterna explícitamente entre razonar en texto y ejecutar una acción, observando el resultado antes del siguiente razonamiento. Es el patrón base de casi todos los frameworks actuales.

Plan-and-Execute

El agente genera primero un plan completo de pasos, y luego lo ejecuta (con posibilidad de replanificar si un paso falla). Reduce el número de llamadas al modelo comparado con ReAct puro, a costa de menos adaptabilidad paso a paso.

Reflection / Self-critique

Después de producir una salida, un segundo paso (a veces el mismo modelo, a veces otro) la evalúa contra criterios explícitos y decide si iterar. Mejora calidad en tareas de generación de código o contenido, al costo de más latencia y tokens.

Orchestrator-Worker

Un agente orquestador descompone la tarea y delega sub-tareas a agentes "worker" especializados, agregando después sus resultados. Es la base conceptual de casi todos los sistemas multiagente.

Cuándo usar ReAct

Tareas exploratorias donde el siguiente paso depende fuertemente del resultado anterior (debugging, investigación).

Cuándo usar Plan-and-Execute

Tareas con estructura predecible donde el costo de replanificar constantemente no se justifica (pipelines conocidos).

  Thought → Action → Observation → Thought → Action → ...
  
  LLM razona qué hacer, ejecuta una herramienta, observa el resultado,
  razona de nuevo. Loop hasta completar la tarea o alcanzar max_steps.

Patrones de flujo

PATRÓN 1
Map-reduce

Procesar N documentos en paralelo (map) y agregar los resultados (reduce). Ideal para resumir grandes volúmenes de información.

PATRÓN 2
Parallelization

Ejecutar múltiples sub-agentes concurrentemente para distintas sub-tareas. LangGraph soporta branches paralelas nativas.

PATRÓN 3
Evaluator-optimizer

Un agente genera, otro evalúa la calidad. Si no pasa el umbral, el generador itera. Loop de mejora automática.

PATRÓN 4
Subgraph

Grafos anidados donde un nodo padre delega a un subgrafo completo. Permite composición y reutilización de flujos.

Regla de diseño Envuelve los pasos no deterministas del LLM en una estructura determinista: estados explícitos, límites de pasos, validación entre etapas y puntos de aprobación. La libertad del agente debe ser la mínima necesaria para la tarea.
