Términos que aparecen en el handbook y en conversaciones técnicas sobre IA, en orden alfabético.

TérminoDefinición
A2AProtocolo Agent2Agent para comunicación y delegación de tareas entre agentes de distintos sistemas.
AgenteSistema donde un LLM decide en un loop qué herramientas usar y cuándo ha terminado.
AI GatewayPunto central por donde pasan las llamadas a modelos: autenticación, cuotas, routing, caché, trazas y costos.
AlucinaciónContenido plausible pero falso o no soportado por las fuentes.
ANNApproximate Nearest Neighbors: búsqueda aproximada de vecinos más cercanos (HNSW, IVF) en bases vectoriales.
BM25Algoritmo clásico de ranking léxico por coincidencia de términos.
ChunkFragmento de documento que se indexa y recupera como unidad.
Context engineeringDiseño de qué información entra en la ventana del modelo en cada llamada.
Context windowMáximo de tokens (entrada + salida) que el modelo procesa en una llamada.
Cross-encoderModelo que evalúa conjuntamente consulta y documento; base de los re-rankers.
CuantizaciónRepresentar pesos con menos bits para reducir memoria y acelerar inferencia.
DestilaciónEntrenar un modelo pequeño con salidas de uno grande.
DPODirect Preference Optimization: alineamiento con pares de respuestas preferidas y rechazadas.
EmbeddingVector numérico que representa el significado de un texto u otro objeto.
EvalsEvaluaciones automatizadas de la calidad de un sistema de IA sobre un conjunto de casos.
Few-shotIncluir ejemplos de entrada y salida en el prompt.
Fine-tuningContinuar el entrenamiento de un modelo con datos propios para ajustar su comportamiento.
Golden datasetConjunto curado de casos con respuestas o criterios esperados, usado para evaluar.
GroundingAnclar la respuesta en fuentes provistas en el contexto.
GuardrailsControles de entrada y salida (filtros, validaciones, límites, aprobaciones) alrededor del modelo.
HNSWÍndice vectorial basado en grafos jerárquicos; alto recall con más memoria.
Human-in-the-loopPunto de aprobación o revisión humana dentro de un flujo automatizado.
HyDEGenerar un documento hipotético para usarlo como consulta de búsqueda.
InferenciaEjecutar un modelo entrenado para obtener una salida.
KV cacheKeys y values de atención guardados para no recalcular el prefijo al generar cada token.
LLM-as-judgeUsar un modelo con una rúbrica para calificar salidas de otro.
LoRA / QLoRAFine-tuning eficiente que entrena matrices pequeñas añadidas al modelo congelado (QLoRA: sobre modelo cuantizado).
MCPModel Context Protocol: estándar abierto para exponer herramientas, recursos y prompts a aplicaciones con modelos.
MoEMixture of Experts: arquitectura que activa solo algunos sub-bloques por token.
MRR / NDCGMétricas de ranking: posición del primer resultado relevante / calidad del orden ponderada por posición.
Prompt cachingReutilización del procesamiento de un prefijo de prompt idéntico entre llamadas.
Prompt injectionInstrucciones maliciosas, directas o dentro de contenido leído, que alteran el comportamiento del modelo.
RAGRetrieval-Augmented Generation: recuperar información relevante e incluirla en el contexto antes de generar.
ReActPatrón de agente que alterna razonamiento, acción y observación.
Re-rankingReordenar candidatos recuperados con un modelo más preciso.
RLHFAprendizaje por refuerzo con retroalimentación humana para alinear el modelo.
RRFReciprocal Rank Fusion: combina rankings de varios buscadores.
SFTSupervised Fine-Tuning con pares instrucción → respuesta.
Structured outputsSalida del modelo validada contra un esquema (normalmente JSON Schema).
TemperatureParámetro que controla la aleatoriedad del muestreo.
TokenUnidad mínima de texto que procesa el modelo.
Tool use / function callingCapacidad del modelo de solicitar la ejecución de funciones definidas por la aplicación.
TTFTTime to first token: tiempo hasta el primer token de la respuesta.
Vector storeBase de datos optimizada para almacenar y buscar embeddings.
