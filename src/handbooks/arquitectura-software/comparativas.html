Monolito vs Microservicios

Dimensión Monolito Microservicios Recomendación
Complejidad inicial Baja Alta (infra, networking) Monolito para proyectos nuevos
Escalabilidad Todo o nada Por componente Microservicios para alta escala
Despliegue Todo junto Independiente Microservicios para CD frecuente
Debugging Stack trace claro Trazas distribuidas requeridas Monolito más fácil de debuggear
Transacciones ACID nativas Saga patterns necesarios Monolito para consistencia fuerte
Tamaño de equipo Ideal < 15 personas Escala con equipos grandes Conway's Law: organización → arquitectura
Latencia interna In-process (microsegundos) Red (milisegundos) Monolito para operaciones críticas

On-Premise vs Cloud

Dimensión On-Premise Cloud
Modelo de costo CapEx (inversión capital) OpEx (gasto operativo)
Time to provision Semanas o meses Minutos
Elasticidad Limitada y costosa Automática e ilimitada
Control de datos Total Depende del contrato
Cumplimiento (Compliance) Máximo control Certificaciones disponibles
Equipo requerido Ops + sysadmins dedicados Reducido
Disponibilidad global Costosa y compleja Nativa (regiones y AZs)

Serverless vs Contenedores

Dimensión Serverless (FaaS) Contenedores (K8s)
Granularidad Función individual Servicio completo
Cold start 100ms – 2s Predecible (always-on)
Estado Stateless obligatorio Stateful posible
Costo en idle $0 (no ejecuta) Paga aunque no haya tráfico
Max duración 15 min (Lambda) Sin límite
Vendor lock-in Alto Bajo (OCI estándar)
Observabilidad Limitada sin herramientas Completa con Prometheus/OTel
Ideal para Eventos, webhooks, ETL APIs, servicios de larga duración
