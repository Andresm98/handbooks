🌐 Tipos de Nube y Estrategias de Despliegue

🔒 Private Cloud / On-Premise

Infraestructura propia o gestionada exclusivamente para una organización. Control total, costos fijos altos.

  • Cumplimiento regulatorio estricto
  • Datos altamente sensibles
  • Latencia ultra-baja requerida

🌍 Public Cloud

Infraestructura compartida gestionada por el proveedor (AWS, Azure, GCP). Pago por uso, elasticidad máxima.

  • Startups y proyectos con crecimiento variable
  • Menor inversión inicial (CAPEX → OPEX)

🔀 Hybrid Cloud

Integración de nubes de diferentes tipos (public + private/on-premise). Conectadas via VPN o Direct Connect.

  • Mantener legacy systems críticos on-prem
  • Migración gradual a la nube
  • Datos sensibles on-prem + cómputo en cloud

🌐 Multi-Cloud

Uso de múltiples nubes del mismo tipo (dos o más proveedores públicos) para diferentes propósitos.

  • Evitar vendor lock-in
  • Best-of-breed: mejor servicio de cada proveedor
  • Redundancia geográfica/proveedor

📦 Modelos de Servicio Cloud

Modelo Gestión Usuario Gestión Proveedor Ejemplos
IaaS — Infrastructure as a Service OS, runtime, apps, data Virtualización, servidores, storage, red EC2, Azure VMs, Compute Engine
PaaS — Platform as a Service Apps y data Todo el stack de infraestructura + OS Heroku, App Engine, Azure App Service
SaaS — Software as a Service Solo configuración de uso Todo el stack completo Gmail, Salesforce, Slack, Office 365
BaaS — Backend as a Service Lógica frontend + config Backend completo (auth, DB, storage) Firebase, Supabase, Auth0
FaaS — Function as a Service Solo código de función Runtime, escalado, infraestructura AWS Lambda, Azure Functions, Cloud Run
Serverless (general) Lógica de negocio Toda la infraestructura + servers Lambda + API Gateway + DynamoDB

🏛️ AWS Well-Architected Framework

Marco de referencia de AWS para evaluar arquitecturas cloud. Compuesto por 6 pilares:

🔒 Security

  • Least privilege IAM
  • Encriptación at-rest y in-transit
  • Detective controls (GuardDuty, CloudTrail)
  • Defense in depth

⚡ Reliability

  • Multi-AZ deployments
  • Auto Scaling groups
  • Circuit breakers y retries
  • Disaster Recovery (RPO/RTO)

🚀 Performance Efficiency

  • Right-sizing de instancias
  • Caching (ElastiCache, CloudFront)
  • Arquitectura event-driven
  • Benchmarking continuo

💰 Cost Optimization

  • Reserved Instances / Savings Plans
  • Spot Instances para workloads tolerantes
  • AWS Trusted Advisor
  • Eliminar recursos ociosos

⚙️ Operational Excellence

  • IaC para todas las operaciones
  • Runbooks y playbooks automatizados
  • Observabilidad completa
  • Small, frequent, reversible changes

🌱 Sustainability

  • Maximizar utilización de recursos
  • Usar regiones más eficientes energéticamente
  • Arquitecturas serverless (pago por uso real)
