Un agente es un LLM al que se le da un objetivo, un conjunto de herramientas, y la capacidad de ejecutar un loop: observar, decidir, actuar, observar el resultado, y repetir hasta cumplir el objetivo o alcanzar un límite. La diferencia con un simple prompt-respuesta es que el agente controla su propio flujo de pasos.

Un agente es un sistema donde un LLM controla un loop de razonamiento-acción iterativo. A diferencia de un pipeline RAG estático, el agente decide dinámicamente qué acciones tomar, en qué orden, y cuándo ha terminado.

"Un pipeline ejecuta pasos predefinidos. Un agente decide qué pasos ejecutar."

El loop agéntico canónico

┌───────────────────────────┐ │ │ ▼ │ ┌─────────┐ ┌──────────┐ ┌──┴───────┐ │ Percibir│───►│ Planificar│──►│ Actuar │ │ (estado,│ │ (siguiente│ │(tool call)│ │ contexto)│ │ paso) │ └──┬───────┘ └─────────┘ └──────────┘ │ ▲ │ └─────── Observar resultado ┘ Termina cuando: objetivo cumplido, límite de pasos alcanzado, o requiere intervención humana.

El loop ReAct (Reason + Act)

ReAct es el patrón fundamental de los agentes modernos. El modelo alterna entre pensar (Thought), actuar (Action), y observar el resultado (Observation) hasta completar la tarea. 

--- Iteración 1 ---
Thought: Necesito saber el precio actual de AAPL.
Action: search_web("AAPL stock price today")
Observation: AAPL está a $189.30

--- Iteración 2 ---
Thought: Ahora necesito calcular la variación vs el precio de ayer ($186.50).
Action: calculate("(189.30 - 186.50) / 186.50 * 100")
Observation: 1.50%

--- Iteración 3 ---
Thought: Tengo toda la información necesaria. Puedo responder.
Final Answer: AAPL subió un 1.50% hoy, de $186.50 a $189.30.

Componentes de un agente productivo

ComponenteFunción
Modelo baseMotor de razonamiento y decisión en cada paso
Herramientas (tools)Funciones concretas que el agente puede invocar: APIs, bases de datos, búsqueda
Memoria de corto plazoEstado de la tarea actual dentro del context window
Memoria de largo plazoPersistencia entre sesiones, típicamente vía RAG o almacenamiento clave-valor
PlanificadorLógica (a veces el mismo LLM, a veces explícita) que decide el orden de pasos
GuardrailsLímites de pasos, validación de salidas, puntos de aprobación humana
Punto de arquitectura clave
Cuantas más herramientas y más pasos tenga un agente, más importa el diseño de guardrails: límite de iteraciones, validación de cada tool call antes de ejecutarla, y puntos explícitos de "human in the loop" para acciones irreversibles (transferencias, cambios de configuración, envíos externos).

Postulados de sistemas agénticos

POSTULADO P1
Plan antes de actuar

Los agentes que planifican explícitamente antes de ejecutar cometen menos errores irrecuperables que los que actúan directamente.

POSTULADO P2
Mínimo privilegio

Un agente solo debe tener acceso a las herramientas y datos que necesita para su tarea específica. El scope excesivo amplifica los errores.

POSTULADO P3
Checkpointing obligatorio

Flujos agénticos largos deben persistir estado en puntos de control. Un fallo en el paso 8 de 10 no debe reiniciar desde cero.

POSTULADO P4
Human-in-the-loop por defecto

Toda acción irreversible (eliminar datos, enviar emails, ejecutar código) debe requerir confirmación humana hasta que el sistema demuestre confiabilidad.

¿Necesitas realmente un agente?

Un agente cuesta más, tarda más y es menos predecible que un flujo fijo. Antes de elegirlo, verifica cuatro condiciones:

CriterioPreguntaSi la respuesta es "no"
Complejidad¿La tarea tiene múltiples pasos difíciles de especificar de antemano?Usa una llamada o un workflow fijo.
Valor¿El resultado justifica más costo y latencia?Simplifica.
Viabilidad¿El modelo es capaz en este tipo de tarea (medido, no supuesto)?Descompón o cambia de enfoque.
Costo del error¿Los errores se detectan y revierten (pruebas, revisión, rollback)?Añade aprobación humana o limita a solo lectura.

Autonomía como dial, no como interruptor

NivelEl agente…Ejemplo
SugerirPropone; una persona ejecutaBorrador de respuesta a un reclamo.
Actuar con aprobaciónPrepara la acción; se ejecuta tras confirmaciónReverso de un cargo, con aprobación del analista.
Actuar y notificarEjecuta acciones reversibles y avisaRe-etiquetar tickets, crear tareas.
Autónomo acotadoEjecuta dentro de un presupuesto y un sandboxAgente de código en un contenedor efímero que abre un pull request.

El nivel se decide por acción, no por agente: el mismo agente puede leer libremente, escribir con notificación y mover dinero solo con aprobación.
