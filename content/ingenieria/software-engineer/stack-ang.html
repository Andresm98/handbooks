Junior Componentes, templates y routing

Data Binding — los 4 tipos
interpolation · property · event · two-way

Angular tiene cuatro formas de conectar el componente con la vista: Interpolación muestra valores. Property binding pasa datos al DOM. Event binding escucha eventos del DOM. Two-way binding sincroniza en ambas direcciones (típico en formularios).

Angular Template HTML
<!-- 1. Interpolación: Component → DOM (solo texto) -->
<h1>Hola, {{ usuario.nombre }}</h1>
<p>Total: {{ precio * cantidad | currency }}</p>

<!-- 2. Property binding: Component → DOM (cualquier prop) -->
<img [src]="usuario.avatar" [alt]="usuario.nombre">
<button [disabled]="!formulario.valid">Guardar</button>

<!-- 3. Event binding: DOM → Component -->
<button (click)="guardar()">Guardar</button>
<input (input)="onInput($event)">

<!-- 4. Two-way binding: sincronización bidireccional -->
<input [(ngModel)]="usuario.nombre">
<!-- Equivale a: -->
<input [ngModel]="usuario.nombre" (ngModelChange)="usuario.nombre = $event">
Comunicación entre componentes
@Input · @Output · EventEmitter · padre-hijo

@Input() pasa datos del padre al hijo. @Output() con EventEmitter emite eventos del hijo al padre. Para comunicación entre componentes no relacionados, usar un servicio con Subject o BehaviorSubject.

TypeScript · Angular
@Component({ selector: 'app-producto', template: ` <div>{{ producto.nombre }} — {{ producto.precio | currency }}</div> <button (click)="agregar()">Agregar al carrito</button> ` }) export class ProductoComponent { @Input({ required: true }) producto!: Producto; @Output() agregado = new EventEmitter<Producto>(); agregar() { this.agregado.emit(this.producto); } } // En el padre: // <app-producto [producto]="item" (agregado)="onAgregado($event)">
Routing y Lazy Loading
RouterModule · loadComponent · Guards · ActivatedRoute

El router de Angular gestiona la navegación SPA sin recargar la página. El Lazy Loading carga los módulos/componentes solo cuando el usuario navega a esa ruta, reduciendo el bundle inicial. Los Guards protegen rutas (autenticación, permisos).

TypeScript · app.routes.ts (Angular 17+)
export const routes: Routes = [ { path: '', redirectTo: '/home', pathMatch: 'full' }, // Lazy loading de standalone component { path: 'productos', loadComponent: () => import('./productos/productos.component') .then(m => m.ProductosComponent) }, // Ruta protegida con guard funcional { path: 'admin', canActivate: [authGuard], loadComponent: () => import('./admin/admin.component') .then(m => m.AdminComponent) } ]; // Guard funcional (Angular 15+) export const authGuard: CanActivateFn = () => { const auth = inject(AuthService); const router = inject(Router); return auth.isLoggedIn() || router.createUrlTree(['/login']); };

Mid RxJS, estado y formularios reactivos

RxJS — operadores esenciales
switchMap · mergeMap · combineLatest · takeUntilDestroyed

RxJS gestiona flujos de datos asíncronos. switchMap cancela la petición anterior si llega una nueva (ideal para búsquedas). mergeMap no cancela, ejecuta todas en paralelo. combineLatest combina múltiples observables emitiendo cuando cualquiera cambia.

TypeScript · Angular
@Component({ ... }) export class BuscadorComponent { private destroyRef = inject(DestroyRef); productos$ = toObservable(this.searchTerm).pipe( debounceTime(300), distinctUntilChanged(), switchMap(term => // cancela búsqueda anterior term.length > 2 ? this._api.search(term) : of([]) ), takeUntilDestroyed(this.destroyRef) // auto-unsubscribe ); // Combinar múltiples fuentes vm$ = combineLatest({ usuario: this._auth.currentUser$, permisos: this._permisos.permisos$, config: this._config.config$ }).pipe( map(({ usuario, permisos, config }) => ({ nombre: usuario.nombre, puedeEditar: permisos.includes('editar'), theme: config.theme })) ); }
💡 Usa el async pipe en el template (*ngIf="vm$ | async as vm") — maneja la suscripción y desuscripción automáticamente. Es la forma más segura de consumir observables en templates.
Reactive Forms
FormGroup · FormControl · validators · FormBuilder

Los Reactive Forms definen la estructura del formulario en TypeScript, no en el template. Esto da control total sobre validaciones, valores dinámicos, y hace el código testeable. Son la opción recomendada para formularios complejos.

TypeScript · Angular
export class RegistroComponent { private fb = inject(FormBuilder); form = this.fb.group({ nombre: ['', [Validators.required, Validators.minLength(3)]], email: ['', [Validators.required, Validators.email]], password: this.fb.group({ valor: ['', Validators.minLength(8)], confirmar: '' }, { validators: passwordsMatch }) // validator de grupo }); submit() { if (this.form.invalid) return; const data = this.form.getRawValue(); // data está completamente tipado } } // Custom validator const passwordsMatch: ValidatorFn = (group) => { const pass = group.get('valor')?.value; const confirm = group.get('confirmar')?.value; return pass === confirm ? null : { noCoinciden: true }; };

Senior Signals, performance y Angular moderno

Signals — reactividad granular
signal() · computed() · effect() · toSignal()

Los Signals (Angular 17+) son el nuevo modelo de reactividad. A diferencia de los Observables, son síncronos y Angular sabe exactamente qué componentes dependen de cada signal. Esto permite actualizaciones quirúrgicas sin necesidad de Zone.js ni markForCheck().

TypeScript · Angular 17+
@Component({ template: ` <p>Contador: {{ contador() }}</p> <p>Doble: {{ doble() }}</p> <button (click)="incrementar()">+1</button> ` }) export class ContadorComponent { // Signal writable contador = signal(0); // Computed: se recalcula solo cuando contador cambia doble = computed(() => this.contador() * 2); incrementar() { this.contador.update(v => v + 1); // o: this.contador.set(this.contador() + 1); } } // Interop con RxJS private _usuario$ = inject(AuthService).currentUser$; usuario = toSignal(this._usuario$, { initialValue: null }); // Effect: código que corre cuando un signal cambia constructor() { effect(() => { console.log('Contador cambió a:', this.contador()); }); }
Change Detection OnPush
zona · markForCheck · immutability · performance

Por defecto, Angular verifica todos los componentes en cada evento. Con OnPush, un componente solo se re-renderiza si sus @Input() cambian por referencia, si un observable emite, o si llamas markForCheck() manualmente. Esencial para apps de alto rendimiento.

TypeScript · Angular
@Component({ selector: 'app-lista-productos', changeDetection: ChangeDetectionStrategy.OnPush, template: ` @for (p of productos(); track p.id) { <app-producto [producto]="p" /> } ` }) export class ListaProductosComponent { // Signal como @Input — OnPush detecta el cambio productos = input.required<Producto[]>(); // Con Observable: usar async pipe + OnPush es la combinación ideal // El async pipe llama markForCheck() automáticamente } // ❌ Trampa: mutaciones no disparan OnPush this.productos.push(nuevoProducto); // NO actualiza la vista // ✅ Crear nueva referencia this.productos = [...this.productos, nuevoProducto];
💡 Con Signals + Standalone Components + OnPush, Angular puede eventualmente funcionar sin Zone.js (zoneless). Es la dirección del framework para el futuro.
Deferrable Views (@defer)
lazy rendering · @placeholder · @loading · interaction trigger

El bloque @defer (Angular 17+) carga componentes de forma diferida directamente desde el template, con control de cuándo hacerlo (al hacer scroll, al interactuar, tras N ms) y qué mostrar mientras tanto.

Angular Template HTML
<!-- Cargar solo cuando el usuario llega a este elemento --> @defer (on viewport) { <app-grafico-complejo [data]="data" /> } @loading { <div class="skeleton">Cargando gráfico...</div> } @placeholder { <div>Haz scroll para ver el gráfico</div> } @error { <p>Error al cargar el gráfico</p> } <!-- Cargar al hacer hover --> @defer (on hover) { <app-detalle-producto [id]="productoId" /> } <!-- Cargar después de 2 segundos --> @defer (after 2s) { <app-chat-widget /> }

Lead / Arch Arquitectura frontend y Module Federation

Micro Frontends con Module Federation
shell · remote · shared · Nx workspace

Module Federation (Webpack 5) permite que múltiples apps Angular se carguen en runtime compartiendo dependencias. Un shell carga remotes (otros deploys) como si fueran módulos locales. Cada equipo deploya su micro-frontend independientemente.

TypeScript · webpack.config.js (Shell)
const { ModuleFederationPlugin } = require('webpack/lib/container/ModuleFederationPlugin'); module.exports = { plugins: [ new ModuleFederationPlugin({ name: 'shell', remotes: { pedidos: 'pedidos@http://localhost:4201/remoteEntry.js', catalogo: 'catalogo@http://localhost:4202/remoteEntry.js' }, shared: { '@angular/core': { singleton: true, strictVersion: true }, '@angular/router': { singleton: true } } }) ] }; // En las routes del shell — lazy load de remote { path: 'pedidos', loadComponent: () => import('pedidos/PedidosComponent') .then(m => m.PedidosComponent) }
💡 Con Nx, gestionar un monorepo con múltiples apps Angular y librerías compartidas es mucho más manejable. Usa nx graph para visualizar dependencias y affected para solo buildear lo que cambió.
